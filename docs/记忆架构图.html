项目记忆修复架构 · 路线 A（瘦身版）（示意）
写入链路 → 条目化存储 → 分层读取注入 · 修复点①~⑤对应问题清单 · 治理机制延后、提炼为开关
① 写入链路（任务完成后）
任务完成 · 主理人 merge 结果
▼
空值保护：结果为空 → 不落库 修①
▼
摘要截断 + 省略号（默认，零 LLM 依赖）
可选开关：LLM 提炼 2~5 条要点，失败降级 修③
▼
标题用任务名截断 ≤60 字 修②
▼
按「项目+标题」去重：同任务重跑命中同标题 → 更新不追加（source_task_id 仅溯源） 修⑤
▼
写入 project_memories + 显式同步 FTS5
② 存储层（条目化，替代单字段）
核心记忆 Core（常驻）
pinned=1 + 最近 5 条 · 注入 ≤1500 字
▾
归档记忆 Archival（按需）
kind=auto / manual · FTS5 检索 Top-5
软上限 1000 条：仅提示，不自动删除
字段：id / project_id / kind / title / content / tags / source_task_id / pinned / 时间戳
检索层可插拔：FTS5（默认）→ 向量检索（触发条件后启用）
③ 读取链路（每次 Agent 调用）
核心块：pinned + 最近 5 条（始终注入）
▲
检索块：关键词 ≥2 且 FTS（trigram）有命中才注入 Top-5（防噪音；bm25 仅排序不定阈值）
▲
总量预算 ≤3000 字，先保核心块
▲
注入子 Agent（manager._call_agent）
＋ 新增主理人 plan / merge（orchestrator._call_agent）修④
修复点：① 空记录不落库 · ② 标题不用需求全文 · ③ 截断带省略标记 · ④ 主理人同样注入记忆 · ⑤ 同任务去重更新。
瘦身决策：淘汰/衰减治理延后（软上限仅提示）；LLM 提炼为配置开关（默认关）；检索层 `backend` 可插拔，触发条件（条目>500 且实测漏召回）后换向量实现。
参考：Mem0（记忆即一等对象 / 提取式 / update 语义）、MemGPT·Letta（Core-Archival 分层 / 按需检索）。示意结构，非实现代码。
